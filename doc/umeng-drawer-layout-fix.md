# 友盟抽屉布局修复（2026-10-29）

友盟真实页面为 `#root` 设置了 `padding-left: calc(100vw - 100%)`。旧抽屉缩小 HTML 宽度后，视口宽度保持不变，该滚动条补偿被误算成抽屉的 520px，原页面因而右移。

## 实现

- 通用布局控制器位于 `src/ui/page-layout.js`，无域名判断。
- 友盟内置配置声明 `presentation.drawerPaddingSelectors: ["#root"]`。此字段仅接受最多 8 个简单 ID / class 选择器。
- 展开前读取正常布局下目标的左内边距，在整个开合期间保持该值；结束后恢复原内联值及优先级。正常滚动条补偿可能是 12px，不会统一清零。
- 旧内置覆盖没有该字段时继承内置默认值；显式 `[]` 关闭此修复。
- 原网页宽度和面板位移使用 320ms 同步缓动。以当前实际 CSS 宽度开始，支持中途反向、窗口缩放、原有较窄根节点、边框/内边距和占位滚动条；关闭结束后完整恢复。
- 减少动态效果时不执行动画。视口不超过 760px 时保持原来的覆盖式行为，不强行挤压网页。

## 验证

- `npm test`：159 项通过，其中 9 个布局回归场景。
- `npm run check` 与 `npm run test:watch` 通过。
- Ego Lite 真实友盟页面使用实际布局模块验证：开合过程中左侧不再增加抽屉宽度；浏览器真实 CSS 动画时间轴在 0 / 80 / 160 / 240 / 320ms 的中间宽度连续，快速反向接续当前位置，减少动态效果立即还原。
- 实际完整构建配合合成 BugDone / 友盟 / GitHub 页面验证：BugDone 详情框让位 520px；友盟旧覆盖继承修复；切换浮窗后页面宽度及内联内边距均恢复。
- 标准模式合成页验证 1100 / 1800 / 700 / 2000px 视口：保持正常 0 / 12px 滚动条补偿，未篡改友盟的 1280px 最小宽度。

## 边界

友盟的最小宽度仍然保留；窄屏时原网页可能需要横向滚动。本次未增加自动浮窗回退，也未改动 FastlaneTool 原生分栏。没有创建真实任务、上传附件或把真实页面数据加入仓库。用户人工验收通过，修复版本为 3.0.1。
